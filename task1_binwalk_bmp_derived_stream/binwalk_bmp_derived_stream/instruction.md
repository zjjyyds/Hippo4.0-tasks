# 固件位图资源中的 DBSF 派生数据流分析

在某些嵌入式设备固件中，部分界面位图（BMP）资源的像素数据内携带有辅助的二级诊断与配置数据流（DBSF v2）。这些数据流在固件中的分布与封装方式未有任何文档留存，以样本档案的声明为准。

请为 Binwalk 增加针对此类派生数据流的分析能力（背景与任务要求见协议组归档的现场笔记）：
`/task_docs/derived-bitmap-stream.md`

**注意**：该格式的厂商工具链与文档均已失传，现场笔记不含任何线格式细节。唯一权威参考是从生产设备回收的样本档案及其校验清单：
`/task_docs/samples/`（含 `MANIFEST.md`，逐样本声明了必须恢复/必须不恢复的结果）。
符合要求的实现必须能从每个样本中精确复现清单所声明的结果；验收所用的是同一（失传）工具链产出的未见过的固件镜像。

### 交付要求

1. **协议支持**：依据样本档案所定义的行为，从固件数据中完整恢复 DBSF v2 数据流。
2. **分析集成**：提取出的载荷需复用既有的签名分析引擎处理（继承 include/exclude 过滤），并对恢复出的载荷递归执行派生流分析（最外层输入扫描深度为 1，最大递归深度为 3，深度 4 及更深层的嵌套流不得继续扫描或报告），最终在分析结果 `AnalysisResults` 的 `derived` 字段中以结构化形式呈现。
3. **接口与兼容性**：该能力必须通过库接口控制（默认关闭，保持原有分析行为不变）：
   `binwalker.enable_derived_streams(true)`
   不得引入外部运行时依赖（不得修改 `Cargo.toml`/`Cargo.lock` 或调用外部子进程），既有库单元测试与全部内置提取器回归测试必须全部保持通过。
4. **载荷交付**：每个派生结果（含嵌套结果）必须公开 `payload: Vec<u8>`，并在 JSON 中序列化为完整载荷字节数组。`total_payload_size` 必须等于该数组长度。验收将独立计算载荷 SHA-256，并用固定版本的 Binwalk 对载荷重新扫描，核对子签名及过滤行为；只返回摘要或描述字符串不算恢复载荷。
