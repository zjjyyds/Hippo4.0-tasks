# D4 TCP 证据重建任务：测试分析与归因报告

## 1. 任务背景与公开要求
D4 Network Forensics Suite 是一个基于 Python 标准库实现的轻量级网络取证分析套件。在网络取证调查场景中，捕获的原始 PCAP 文件经常包含重传、乱序、丢失以及旁路注入伪造的混淆数据包。

本题要求为 `NetworkForensics.full_analysis()` 增加 `"tcp_evidence"` 能力，按方向四元组 `(src_ip, sport, dst_ip, dport)` 恢复每个独立 TCP 连接的载荷证据。与常规网络协议栈不同，法庭科学取证严格遵循**证据一致性**约束：
1. **禁止多数投票与覆盖**：同一序列区间若存在不同载荷字节（冲突重传），冲突位置必须标记为不确定字节 `'?'`（`0x3F`），其余一致字节正常确认为 confirmed。
2. **$2^{32}$ 序列号模算回绕**：流重组必须正确处理 $2^{32}-1 \to 0$ 的循环边界。
3. **SYN/FIN 消耗序列号**：SYN 与 FIN 标志各消耗 1 字节序列空间，载荷数据起始于 `ISN + 1`。
4. **同四元组连接代次隔离**：以 SYN、FIN 完成或 RST 划分连接生命周期，代次（generation）自 0 开始递增，前一代次的残留数据绝不能泄漏至后一代次。
5. **链路 Padding 剥离**：根据 IPv4 Total Length、IHL 和 TCP Data Offset 计算真实载荷边界，严禁将以太网 64 字节最小帧填充（Padding）当作应用层数据。

## 2. 验收依据与覆盖矩阵（48 组条件检查）
测试套件由 24 组确定性生成的随机 PCAP 场景构成，每组场景分别以**捕获原始顺序**和**倒序/置换顺序**运行两次独立分析（共 48 组断言），确保模型实现的是基于序列空间的严谨状态机，而非依赖文件写入顺序的投机逻辑。

| 用例编号与场景 | 核心检验能力 | 对应公开规范 |
| :--- | :--- | :--- |
| **Case 01：基础连续握手流** | 验证基本 SYN 握手、ISN+1 载荷偏移及 FIN 终止 | 需求 1、2、4 |
| **Case 02：完全乱序到达重组** | 验证多段载荷乱序到达时的序列空间重组 | 需求 1、3 |
| **Case 03：完全相同重传确认** | 验证重复收包不产生假冲突，confirmed 保持无瑕 | 需求 6 |
| **Case 04：单字节冲突重传** | 验证 `ABCDEF` vs `ABCXEF` 输出 `ABC?EF`，绝杀多数投票 | 需求 6 |
| **Case 05：多字节重叠重传冲突** | 验证复杂重叠切片中部分字节一致、部分字节冲突的复合判定 | 需求 6 |
| **Case 06：未观测到的序列空洞** | 验证丢包间隙产生正确 `gaps` 范围，confirmed 用 `?` 占位 | 需求 6、7 |
| **Case 07：跨越 $2^{32}$ 边界回绕** | 验证从 `0xFFFFFFF0` 连续跨越 0 的循环序列差计算 | 需求 3 |
| **Case 08：回绕伴随乱序到达** | 0 之后的数据包先到，0 之前的数据包后到，检验序列模算 | 需求 3 |
| **Case 09：回绕伴随冲突重传** | 在回绕零点两侧发生冲突重传，检验循环空间下的冲突定位 | 需求 3、6 |
| **Case 10：无 SYN 握手中间捕获** | 抓包自连接中间开始，最早观测序列成为逻辑偏移 0 | 需求 2 |
| **Case 11：FIN 序列空间消耗** | 验证单独的 FIN 包消耗序列号，不产生假载荷与假空洞 | 需求 4 |
| **Case 12：同四元组 FIN 代次演进** | 连续两次完整握手与释放，检验 `generation: 0` 与 `1` 独立性 | 需求 2 |
| **Case 13：同四元组 RST 异常代次演进** | RST 中断前一次会话后立即开启新会话，检验代次隔离 | 需求 2 |
| **Case 14：以太网 64 字节 Padding 剥离** | 检验根据 IP Total Length 剔除以太网填充尾巴的能力 | 需求 5 |
| **Case 15：可变 TCP 选项首部偏移** | 包含 MSS、SACK、Timestamp 等选项，TCP Data Offset > 5 | 需求 5 |
| **Case 16：可变 IPv4 首部长度 (IHL > 5)** | 包含 IP 选项，检验 IHL 正确计算能力 | 需求 5 |
| **Case 17：多并发独立四元组连接** | 验证多个不同连接在同一 PCAP 中的并发解耦 | 需求 1 |
| **Case 18：双向流量方向隔离** | 同一四元组的 Client->Server 与 Server->Client 拆为独立流 | 需求 1 |
| **Case 19：多重连续重叠冲突窗口** | 模拟多次交替重传冲突，检验 `conflicts` 列表排序与字段 | 需求 6、7 |
| **Case 20：纯 ACK 空载荷包过滤** | 连续纯 ACK 包不应延长流的有效载荷跨度 | 需求 4、7 |
| **Case 21：回绕 + 冲突 + Padding 复合** | 组合压力测试：在回绕点发生部分冲突且带以太网填充 | 需求 3、5、6 |
| **Case 22：相同 ISN 的独立代次演进** | 前后两次连接恰巧由操作系统分配了相同 ISN，检验生命周期 | 需求 2 |
| **Case 23：乱序空洞填补与中间冲突** | 乱序填补先前空洞的同时发生部分字节冲突 | 需求 6 |
| **Case 24：大跨度连续回绕长流** | 50 个连续小分片循环跨越 $2^{32}$ 边界，检验长流稳定性 | 需求 3 |

## 3. 防作弊与环境隔离
1. **测试与评分由独立 Verifier 控制**：测试生成器与验证脚本位于独立容器 `/tests/`，未编译进 Agent 运行镜像。
2. **反向乱序双重校验**：所有 24 组 PCAP 均在内存中反转包顺序后重复验证，纯按文本累加或偷看抓包顺序的算法在第 1 题就会失败。
3. **上游回归防退化**：自动执行 D4 原生 18 项单元测试，确保原有统计与 IoC 提取功能 100% 保持兼容。
