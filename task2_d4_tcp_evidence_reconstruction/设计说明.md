# D4 TCP Evidence Reconstruction 题目设计说明

## 一、命题思路与定位
- **题目名称**：`d4_tcp_evidence_reconstruction`
- **领域定位**：攻防安全 / 数字取证（Digital Forensics） / 网络协议逆向
- **技术栈**：Python 3（基于标准库，无复杂外部编译依赖）
- **目标公开项目**：[5h4d0wn1k/d4-net-forensics](https://github.com/5h4d0wn1k/d4-net-forensics)
- **固定基线 Commit**：`06e8f893bc0818327a8d28da4264985cdeb731ab`

传统网络协议分析（如 Wireshark、TCPFlow）的核心目标是“尽可能拼凑出完整会话”供用户浏览；但在对抗取证和入侵检测中，攻击者常常使用旁路注入、TTL 欺骗、乱序混淆制造相互矛盾的重传包。若分析引擎简单地“后包覆盖前包”或“多数投票”，就会凭空伪造事实，破坏司法证据链。

本题要求构建严格遵循**法庭科学证据确定性约束**的 TCP 流恢复模块，核心考察五大深层协议陷阱的综合建模能力。

## 二、核心考察点与能力陷阱
1. **$2^{32}$ 序列空间回绕（Sequence Wrap-around）**：
   TCP 序列号必须按循环模空间计算偏移，直接使用无符号整数比大小会导致序列错位。
2. **SYN / FIN 虚占序列号**：
   握手与断开标志消耗 1 序列号，数据偏移必须严格锚定在 `ISN + 1`。
3. **冲突重传的证据不确定性（`?` 占位）**：
   同一序列偏移上出现不同字节证据时，不得采用多数表决或盲目覆盖，必须标记为 `'?'`。
4. **同四元组连接代次隔离（Generational Lifecycle）**：
   高频网络环境下同一四元组可能快速释放并重新建立连接，前一代次的残留报文绝不能跨越生命周期污染新连接。
5. **链路层 64 字节 Padding 剥离**：
   必须准确利用 IPv4 Total Length、IHL 和 TCP Data Offset 计算真实载荷边界，剔除以太网填充。
